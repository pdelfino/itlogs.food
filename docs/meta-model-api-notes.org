* The API in one table
| Thing            | Value                                                                                   |
|------------------+-----------------------------------------------------------------------------------------|
| Base URL         | https://api.meta.ai/v1 (OpenAI-compatible: Responses API, Chat Completions; Anthropic Messages too) |
| Auth             | =Authorization: Bearer $MODEL_API_KEY=; keys look like =LLM_<id>_<secret>=; dashboard, API keys tab |
| Vision + text    | =muse-spark-1.3= (1M context; audio input degraded on 1.3, use Voice Transcribe); =muse-wonder-1.0= for long agentic work |
| Speech to text   | =muse-voice-transcribe-1.0=: realtime =wss://api.meta.ai/v1/asr/realtime= (auth in the handshake JSON, PCM 24 kHz 16-bit mono, modes PUSH_TO_TALK, ENDPOINTING, DIARIZATION) or POST /v1/asr/transcribe (WAV, 10 min, 32 MB) |
| Image generation | =muse-image-1.0=, USD 0.01 per image                                                    |
| Structured output | Chat Completions =response_format: {type: json_schema, json_schema: {...}}= (constrained decoding, guaranteed shape; no recursive schemas); Responses API uses =text.format= |
| Open weights     | Muse Glimmer 30B dense, Apache 2.0, GGUF Q4_K_M 17 GB plus a 1.4 GB vision projector, runs with llama.cpp b10353 or newer (=llama serve -hf meta-models/Muse-Glimmer-30B-GGUF ...=); Muse Spark Open 816B MoE, hosted only (Baseten, Modal, Fireworks, Groq, Together, OpenRouter) |
| Training on content | Standard-mode model ids do not train on your content; =-contributor= ids do (cheaper). This project uses standard-mode ids. |

* Muse Voice Transcribe realtime
Handshake first frame: ={"authorization": {"accessToken": "Bearer <key>"}, "audioEncoding": "PCM_24KHZ", "model": "muse-voice-transcribe-1.0", "mode": "ENDPOINTING", "languageBias": ["English", "Portuguese"], "keywords": ["reps", "kilos", "set"]}=; then binary PCM frames paced near real time (80 ms frames); events =speechStart=, =transcript= (partial), =speechEnd=, =speechComplete= (the final text, punctuated); ={"type": "endStream"}= to finish. Close codes: 1008 bad pacing or config, 1011 backend (or max session length), 1013 rate limited. The key never goes on the phone: the server holds the ASR socket and the phone streams PCM to the server.

* Muse Spark for the stills
Responses API, user message with =input_text= plus =input_image= whose =image_url= is a base64 =data:image/jpeg;base64,...= string; or Chat Completions with =image_url: {url: ...}=. Muse Spark also does "perception grounding": it can return object coordinates as text, a token-priced alternative to SAM for the dumbbell box; worth a side-by-side on the eval sets.

* Muse Glimmer on this Mac
Apple M4, 32 GB unified memory, llama-server from Homebrew already installed (llama.cpp 0.4.1, build 10964, newer than the b10353 minimum); 35 GB free on disk, so the 17 GB GGUF fits but leaves little room. The 17 GB Q4_K_M GGUF plus the vision projector fits; text-only is enough for corrections, rest phrasing and the agent (#7, option B). Download: =hf download meta-models/Muse-Glimmer-30B-GGUF --local-dir ~/models/muse-glimmer --include "Muse-Glimmer-30B-KQuant-17GB-Q4_K_M.gguf" --include "mmproj-Muse-Glimmer-30B-Q4_K_M.gguf"=. Serve: =llama-server -m ... -a muse-glimmer -ngl 99 -c 32768 --port 8080=. OpenAI-compatible, so the same client code as Baseten with another base URL.
